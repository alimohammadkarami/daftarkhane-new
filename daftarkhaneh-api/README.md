# Daftarkhaneh API — سیستم دبیرخانه شخصی

API ثبت نامه‌های وارده، صادره و داخلی با Node.js + Express + MySQL (معماری MVC).

## ساختار پروژه
```
daftarkhaneh-api/
├── config/db.js              اتصال pool به MySQL
├── database/schema.sql       اسکریپت ساخت دیتابیس و جداول
├── models/letterModel.js     کوئری‌ها + تولید شماره ثبت
├── controllers/letterController.js   اعتبارسنجی و منطق درخواست
├── routes/letterRoutes.js    تعریف مسیرها
├── utils/                    upload.js, jalaali.js, ApiError.js, asyncHandler.js
├── uploads/                  محل ذخیره فایل‌های اسکن‌شده
└── server.js                 نقطه ورود اپلیکیشن
```

## راه‌اندازی

1. نصب پکیج‌ها:
   ```bash
   npm install
   ```

2. ساخت دیتابیس:
   ```bash
   mysql -u root -p < database/schema.sql
   ```

3. کپی فایل env و تنظیم مقادیر:
   ```bash
   cp .env.example .env
   ```

4. اجرا:
   ```bash
   npm start
   ```

## نکته مهم درباره تاریخ نامه

`letterDate` باید **تاریخ شمسی** با فرمت `YYYY-MM-DD` باشد (مثل `1405-05-09`) — کلاینت هیچ تاریخ میلادی ارسال نمی‌کند.
سرور این مقدار را:
1. با `jalaali-js` اعتبارسنجی می‌کند (سال/ماه/روز شمسی معتبر باشد).
2. عیناً در ستون `letter_date_jalali` ذخیره می‌کند (برای نمایش دقیق به کاربر).
3. معادل میلادی‌اش را هم در `letter_date_gregorian` ذخیره می‌کند (فقط جهت استفاده از توابع استاندارد `DATE` در MySQL برای مرتب‌سازی/فیلتر/گزارش‌گیری).
4. سال شمسی را مستقیماً از همین رشته (بدون تبدیل) برای ساخت شماره ثبت استخراج می‌کند.

## نکته مهم درباره شماره ثبت سیستم

فیلد «شماره ثبت سیستم» در فرم (مثل `00142/ص/JBH/1405`) توسط سرور و **به‌صورت خودکار** تولید می‌شود؛
کلاینت آن را ارسال نمی‌کند. فرمت آن:

```
{شماره ترتیبی ۵ رقمی}/{کد نوع نامه}/{کد دبیرخانه از env}/{سال شمسی نامه}
```

- کد نوع نامه: `و` = وارده، `ص` = صادره، `د` = داخلی
- شمارنده به تفکیک سال شمسی و نوع نامه در جدول `letter_sequences` نگهداری و به‌صورت اتمیک (تراکنش + قفل ردیف) افزایش می‌یابد تا در صورت ثبت هم‌زمان چند نامه، شماره تکراری صادر نشود.

## Endpoint ثبت نامه

**POST** `/api/letters`
Content-Type: `multipart/form-data` (به دلیل وجود فایل اسکن)

| فیلد فرم         | نام در بدنه درخواست | الزامی | توضیح                                          |
|------------------|----------------------|--------|-------------------------------------------------|
| نوع نامه          | `letterType`         | بله    | یکی از `incoming` / `outgoing` / `internal`     |
| تاریخ نامه        | `letterDate`         | بله    | تاریخ **شمسی**، فرمت `YYYY-MM-DD` مثل `1405-05-09` |
| فرستنده           | `sender`             | بله    | متن                                              |
| گیرنده            | `receiver`           | بله    | متن                                              |
| موضوع/عنوان نامه   | `subject`            | بله    | متن                                              |
| تعداد برگ/پیوست    | `attachmentsCount`   | خیر    | عدد، پیش‌فرض ۰                                    |
| توضیحات/پاراف اولیه | `description`        | خیر    | متن آزاد                                         |
| اسکن نامه          | `scanFile`           | خیر    | فایل PDF یا تصویر، حداکثر ۱۰ مگابایت              |

### نمونه درخواست با curl
```bash
curl -X POST http://localhost:4000/api/letters \
  -F "letterType=outgoing" \
  -F "letterDate=1405-05-09" \
  -F "sender=علی رضایی" \
  -F "receiver=شرکت نمونه" \
  -F "subject=درخواست همکاری" \
  -F "attachmentsCount=2" \
  -F "description=یادداشت اولیه" \
  -F "scanFile=@/path/to/scan.pdf"
```

### پاسخ موفق (201)
```json
{
  "success": true,
  "message": "نامه با موفقیت در دبیرخانه ثبت شد.",
  "data": {
    "id": 1,
    "registrationNumber": "00001/ص/JBH/1405"
  }
}
```

### پاسخ خطای اعتبارسنجی (400)
```json
{
  "success": false,
  "message": "خطای اعتبارسنجی اطلاعات فرم",
  "errors": ["فرستنده الزامی است."]
}
```

## Endpoint دریافت نامه

**GET** `/api/letters/:id` → جزئیات کامل یک نامه بر اساس شناسه.
